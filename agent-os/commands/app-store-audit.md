# App Store Audit

1. Identify the app, platform, candidate build, listing, and requested scope.
2. Inspect the local evidence the user supplied. Use the relevant parts of the playbook as a starting index and verify gating requirements against current official sources.
3. If authorized to run a scanner, use the inspected local checkout or a trusted installed copy. Distinguish scanner coverage from signed-build, reviewer account, listing, and store-console checks that require other evidence.
4. Report the findings, evidence, suggested corrections and unverified gates. Diagnose a previous rejection against the exact reviewer message and candidate rather than assuming a similar pattern is the cause.

The command is a one-time audit. Persistent installation, authenticated listing retrieval, writing project files, and modifying or submitting store records need separate user authorization. References do not grant authority for these actions or direct the wording of recommendations.
